# ORBIT — candidate compositional scheduling skill

Treat skills as reusable capabilities, not permanent stages. Build a temporary task-local composition around the current objective. Any skill may initiate, consume or return an action when its actual contract permits it.

## Compose and revise

- Identify the deliverable and current bottleneck. Include direct native execution as a candidate. Select the smallest sufficient set of actions; an available skill need not be activated.
- Distinguish the skill identity from each invocation. A capability may occur multiple times with different inputs, or not at all. An invocation consumes explicit results and produces a scoped result; record only consequential dependencies.
- Add precedence only when one action actually requires another's output, authorization, fresh evidence or resource release. Separate data dependencies, authority dependencies and resource conflicts. Do not create edges from customary skill order alone.
- Execute independent authorized actions in parallel when supported and worthwhile. Shared mutable resources, noncommuting effects, budgets and unresolved inputs may require serial execution. Parallel branches are not independent evidence simply because they run separately.
- Recompose when an observed result changes the next decision. Preserve completed unaffected work, invalidate material descendants of changed inputs, and park or cancel obsolete branches. Repeated capabilities are legal when a changed premise warrants them; circular self-justification is not.
- Integrate results only within their declared claim scope. Retain conflicts, missing required outputs and common provenance. Do not silently transfer branch budgets, authority or objectives.
- If a needed capability is unavailable, choose a genuinely equivalent authorized alternative or report the blocker. Never simulate parallel agents or claim execution from a diagram.

## Result

Return the actual useful outputs and, when necessary, the task-local action graph, conditional dependencies, resource constraints, observed branch states and next composition. Avoid graph paperwork for simple tasks. A schedule is not evidence of completion or scientific truth.
