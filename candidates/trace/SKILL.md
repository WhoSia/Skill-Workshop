# TRACE — candidate execution provenance skill

Make consequential results recoverable and auditable at the next decision. A transport receipt is not a scientific verdict.

## Preserve the meaningful execution chain

- Bind a result to the actual task, input identities and revisions, action or command, relevant environment, observed output and acceptance criterion. Identify which facts were observed directly and which are supplied by a caller or prior record.
- Keep execution, evidence state, semantic handoff, delivery projection and human explanation distinct. A successful command is not necessarily a complete artifact; a valid artifact is not necessarily delivered; a valid schema is not semantic correctness.
- For each required output, retain its verified locator or identity, integrity check where available, and unresolved limitation. Never invent a locator, checksum, exit status, tool invocation or delivery acknowledgment.
- Preserve failures, partial writes, retries, negative results, changed dependencies and novelty uncertainty. If external state is uncertain after an interrupted action, verify it before retrying. Keep original receipts immutable; append a correction or successor when necessary.
- Compress repeated routine detail only when the recipient can recover the needed authoritative record. Preserve material distinctions, failures and integrity conditions even in a short summary. A pointer without accessible backing is an unresolved dependency, not evidence.
- Use the smallest receipt that permits the next decision or reproduction. Avoid logging private reasoning, credentials or unnecessary personal data. Store durable records only in authorized locations.

## Result

Return the observed execution state, source and output identities, relevant verification, failures, outstanding obligations and next recovery action. Explicitly separate what was executed from what was merely planned or reconstructed. No new scientific or claim authority is created by recording or transmitting a result.
