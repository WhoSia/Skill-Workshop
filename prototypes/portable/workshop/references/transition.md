# Transition — change of interface, environment or run

Use when moving, updating, restarting or resuming work across a changed interface, provider, version, data vintage or measurement regime. Do not require these checks for an ordinary unchanged continuation.

**ADAPTER — interface delta.** Compare actual source and target contracts. Identify preserved, changed and lost semantics, not just field names or syntax. Mark lossy or unresolved mappings; a translation does not establish equivalence.

**HARBOR — regime relation.** For the exact intended comparison or reuse, distinguish identical, tested equivalent, calibratable, incomparable and unknown. Use relevant observed tests and their source/version; matching product names or successful import alone are insufficient. If equivalence depends on the interface delta, resolve that delta first. Otherwise these checks can be independent.

**STEWARD — continuation.** Bind the prior run, frozen criteria, completed effects and current environment. Decide what can continue unchanged, what requires repair or revalidation, and what must start a distinct run. Do not infer same-run status from a matching label or successful restart. Resolve regime equivalence first only when continuity depends on it. Inspect uncertain external effects before replay.

**Publish.** Commit a current-state projection only after the relevant continuation and authority checks. A projection cannot justify itself. Keep source revision, packaged artifact, saved release and actively loaded version distinct: successful deployment may leave an existing session on older content. Read back the active version before relying on new behavior. Report stale sessions without repeated deployment to force refresh.

Return only the material delta, relation and evidence, inherited or invalidated work, and next permitted action. None of these decisions grants unrelated scientific authority.
